Methodology, in four steps

01Initial assessment: what to scrape
  • paradox.ai/careers is a 404 and Paradox's own openings are on Workday (which acquired Paradox in 2025). The jobs that matter are those Paradox hosts for its clients.
  • Opened known clients in a browser and listed Paradox's fingerprints: DNS alias to *.sites.paradox.ai, POST /api/get-jobs, PDX_… job ids, P1-… Job IDs, apply links on olivia.paradox.ai/co/….
  • Checked 6 early cases (Flynn, Checkers, Chipotle…), the 66 official case studies, and a public source (McHire, McDonald's). Only full Paradox career sites share one API.
→ 14 companies, 23 sites, 131,751 jobs
02Find more career sites (Paradox publishes no client list)
  • crt.sh (Certificate Transparency logs): *.paradox.ai revealed 12 clients with their own instance (FedEx); *.recruiting.com gave 234 names, 15 still pointing to Paradox.
  • Passive DNS, reverse CNAME (WhoisXML): every name ever seen as an alias of *.sites.paradox.ai: 72 names, 55 new sites with jobs.
  • Web search (Google via Bright Data), 3 searches: site:recruiting.com -site:www.recruiting.com (4 new sites), "inurl:/job/P1-" in quotes (3 new), inurl:/job/P1- -site:recruiting.com (run twice, no Paradox site found).
  • Every candidate verified by DNS, then one page view reading get-jobs.
→ 66 companies, 73 sites, 100,153 jobs
03How to scrape the jobs (tested in a browser)
  • From the listing page: POST /api/get-jobs?page_number=N&page_size=20 returns JSON with title, location, description, apply link, ids and totalJob (20 per page tested on Saxton's site, 10 by default). Page 1 also works through the API.
  • The listing page must be the Referer (from a job page the API answers 0 jobs); some sites need the languages ["en"] only.
  • The job page adds the only missing field, datePosted (JSON-LD). On McHire the API stops at 10,000 jobs; a state filter gets under it (other large sites not tested).
04Consolidate the list: the 80 companies with their sites, jobs, ATS and discovery method; one record per job (example records in JSON and CSV).

Limits

  • From a script, Paradox sites answer 403 (AWS WAF token). All counts come from a few normal browser requests per site; no protection, CAPTCHA or cookie was bypassed or reused.
  • Free tools only: crt.sh (free, but large searches time out) and WhoisXML's free trial credits (a few queries). Paid or more reliable tools (Cert Spotter, Censys, full passive DNS plans) would likely find many more sites.
  • Totals are announced, not downloaded. Not exhaustive: each discovery method misses sites, and some edge cases were not covered.

One Paradox site, many ATS

A Paradox career site displays the jobs, but the application can go to another ATS: get-jobs returns them all.

  • Other ATS seen: Workday (17 companies), SuccessFactors, Oracle, UltiPro, ADP, SmartRecruiters, Cornerstone… The apply link's host tells which one handles each job.
  • The reverse too: Checkers, Chipotle, 7-Eleven send jobs to Paradox from their own sites.

How to avoid scraping the same job twice

  • Use uniqueID as the first check: it is enough within a site.
  • Across sites, where uniqueID can change format, match on requisitionID, or reference when it is missing (to be confirmed).
  • Pair it with the ATS read from the apply link; a content hash only flags possible reposts (to be confirmed).
